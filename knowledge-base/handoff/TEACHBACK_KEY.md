## 12 — The loop-safe build playbook

1. The plugin matches the `<promise>` text exactly and instructs the model to emit it only when literally true (`knowledge-base/handoff/prompts/_REPORT_FORMAT.md:6-8`). A promise with variable content can never match, and one that means "done" tempts a stuck loop to lie; `LOOP TERMINAL` is true for `DONE` *and* for an honest `STOPPED(reason)` (`:15-19`), so stopping is always available and `--max-iterations` is the cap for a loop that reaches neither. It must be the last line of the final message (`:43`) — the acceptance run lost an iteration to commentary after it (chapter 12 §5a).
2. That line cannot have come from `pnpm test` any more: since `fd4a22c5` the script is `scripts/test-collection-guard.cjs` (`package.json:15`), which exits non-zero on a shortfall and prints `SHORT BY N` with the missing file names (`scripts/test-collection-guard.cjs:406-415`). A bare `214 passed (215)` means the lanes ran raw — `pnpm test:raw` (`package.json:20`), or with an argument, which disables the floor (`:354`). The loop treats it as a shortfall, never a pass: re-run `pnpm test` with no arguments, copy the guard's summary line into the report, and if it is still short, `STOPPED` — never re-run until the number looks right (R13, `knowledge-base/handoff/prompts/_RAILS.md:158`: report the files *collected*).
3. `STATUS: STOPPED(off-limits)`. `server/services/lookupResolver.ts` is a hand-back file in every template (`knowledge-base/handoff/prompts/_RAILS.md:58-64` — the decision-path engines, the PII vaults, `server/auth.ts`), and "the only fix is in a hand-back file" is an R11 stop condition (`:138-146`). The report carries the hand-back — the line, the change it would need, the owner — and the promise is still emitted, because terminal is not done. Worked example: chapter 12 §5b, step 3.
4. T4 (browser) and T5 (post-merge). For T4 a human starts `PORT=5002 pnpm dev` in the worktree, runs `node scripts/browser-probe.cjs --url http://localhost:5002/<route> --width 320` (and 768, 1280) and pastes the output — a UI claim without it is forbidden (`knowledge-base/handoff/prompts/_RAILS.md:170`; R12 `:147-152`). For T5 a human curls `https://homiquity-production.up.railway.app/api/health` and compares `commit` with the merge SHA (`:171`); `verify-deploy` asks the same question but is `continue-on-error: true` (`.github/workflows/ci.yml:770`) and `main` requires zero checks (FACTS F-44), so its answer blocks nothing.
5. It stages the tightened baseline file explicitly, as its own commit, and names it in the PR body (`knowledge-base/handoff/prompts/_RAILS.md:81-83`; the same for a guard-mandated generated block such as the `DESIGN_SYSTEM.md` §0 table, `:84-89`).
